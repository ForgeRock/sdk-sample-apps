Section 2 — Data Flow & API Calls

How PingOneMFA framework APIs wire to each layer. Does this look correct?

🚀 App Launch

1
AppConfiguration.initialize() → PingOneMFA.initialize(geo: .northAmerica) — called once from PingOneMFASampleApp init
2
AppDelegate.application(_:didFinishLaunching) → registers APNs categories via PingOneMFA.getNotificationCategories(), calls application.registerForRemoteNotifications()

📋 Accounts Screen

1
AccountsViewModel.loadAccounts() → PingOneMFAManager.fetchAccounts()
2
PingOneMFAManager calls PingOneMFA.getDeviceInfo() → stores result in @Published accounts: [PingOneMfaAccount]
3
AccountsViewModel mirrors manager.$accounts via Combine sink → AccountsScreen re-renders
4
Pull-to-refresh calls loadAccounts() again

➕ Pairing (Scanner Screen)

1
User taps + button → AppNavigationCoordinator.showScanner = true → sheet presents ScannerScreen
2
QR decoded OR user types key → ScannerViewModel.handleCode(_ key: String)
3
PingOneMFA.pair(pairingKey: key) — single API call for both QR and manual
4
On success → dismiss sheet → AccountsViewModel.loadAccounts() to refresh list

🔔 Push Notifications

1
AppDelegate.didRegisterForRemoteNotificationsWithDeviceToken → PingOneMFA.setDeviceToken(_ token: Data)
2
Foreground notification → PingOneMFA.processRemoteNotification(userInfo:) → returns MFAPushNotification → stored in PingOneMFAManager.pendingNotification
3
Banner tap → PingOneMFA.processRemoteNotificationAction(identifier:authenticationMethod:userInfo:) → same storage path
4
AccountsScreen observes manager.$pendingNotification — when non-nil, presents NotificationView as a sheet
5
NotificationView: Approve → notification.approveNotification(authMethod: "user", numberChallenge:) / Deny → notification.denyNotification() → dismiss + clear pendingNotification
